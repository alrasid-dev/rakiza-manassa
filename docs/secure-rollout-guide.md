# خطة إدخال المنصة إلى بيئة العمل

## المبدأ التشغيلي

تدخل المنصة إلى بيئة المحكمة على مراحل مضبوطة: بيئة تجريبية ببيانات مصنفة، ثم تجربة وصول محدودة، ثم تشغيل فعلي لوحدة شؤون الملازمين، وبعدها توسع مرحلي. لا ينبغي استيراد الملفات الحقيقية أو تفعيل تكامل Teams أو البريد قبل اعتماد مالك البيانات ومسؤول Microsoft 365.

| المرحلة | مسؤول الجهة | مخرج المرحلة | شرط الانتقال |
|---|---|---|---|
| اعتماد النطاق والبيانات | مالك الأعمال ومدير شؤون الملازمين | قائمة النماذج والبيانات المسموح بنقلها | تصنيف الحقول الحساسة وفترة الاحتفاظ. |
| تسجيل تطبيق المؤسسة | مسؤول Microsoft Entra | معرف المستأجر ومعرف التطبيق وشهادة أو سر محفوظ | اعتماد مسارات إعادة التوجيه ومالك التطبيق. |
| تقييد موارد Microsoft 365 | مسؤول Teams/SharePoint وExchange | صلاحية ملف المتعثرات المحدد وصندوق إشعارات مخصص | اختبار قراءة ملف واحد وإرسال رسالة اختبار محكومة. |
| تجربة وصول محكومة | مدير شؤون الملازمين | مجموعة مستخدمين أولية وصلاحياتها | مراجعة سجل التدقيق واختبار منع التجاوز. |
| تشغيل الوحدة | راعي المشروع | تشغيل المهام والتقارير والإشعارات | اعتماد نتائج تجربة التشغيل وتدريب المستخدمين. |

## المصادقة

يسجل مسؤول المؤسسة تطبيق الويب في مستأجر Microsoft Entra ID، ويضيف رابط إعادة التوجيه الإنتاجي المعتمد. يعتمد التطبيق تدفق تفويض حديثاً برموز قصيرة العمر وتحقق من الحالة ورمز لمرة واحدة، ولا يجمع كلمات مرور Microsoft 365 أو يخزنها. توثق Microsoft مواضع إعداد مسارات إعادة التوجيه وإعدادات OpenID Connect ضمن تسجيل التطبيق.[1]

## Microsoft Teams وملف المتعثرات

يقع ملف Teams فعلياً ضمن مساحة SharePoint أو OneDrive المرتبطة بالفريق. لذلك يمنح التطبيق صلاحية محددة لملف أو مجلد واحد، ثم يمنح مسؤول المورد الوصول الصريح لذلك المورد فقط. تتطلب الصلاحيات المحددة موافقة Entra ومنحاً صريحاً للمورد ورمز وصول مناسباً؛ وبغياب أي منها لا يملك التطبيق الوصول.[2]

## البريد والإشعارات

ينشأ صندوق بريد اختصاصي مثل `court-platform-notifications@…` لا يستخدمه موظف فردي. ويقيد التطبيق إلى هذا الصندوق عبر RBAC للتطبيقات في Exchange Online، الذي يدعم نطاقات موارد دقيقة لصناديق بريد محددة.[3] يحتفظ النظام بنتيجة الإرسال لكل قناة ويعيد المحاولة بصورة مضبوطة عند الفشل العابر دون تكرار الرسالة للمستخدم.

## متطلبات الأمان في التطبيق

| طبقة الحماية | التطبيق في المنصة |
|---|---|
| الهوية | مصادقة مؤسسية، مصادقة متعددة العوامل تفرضها الجهة، والتحقق من نطاق المستأجر. |
| الصلاحيات | أدوار مفصلة، تفويض بمدة زمنية، وفحص الصلاحية في الخادم وليس الواجهة فقط. |
| البيانات الحساسة | تشفير حقول التعريف الحساسة على مستوى التطبيق، وفصل أسرار التكامل عن قاعدة البيانات. |
| الجلسات | رموز قصيرة العمر، ملفات تعريف ارتباط محمية، تجديد مضبوط، وإنهاء مركزي عند الحاجة. |
| التكاملات | أقل صلاحية، مورد Teams محدد، وصندوق بريد إشعارات محدد. |
| التدقيق | سجل دائم للأفعال الإدارية، الاستيراد، الاعتمادات، وتغييرات الصلاحيات. |
| التشغيل | نسخ احتياطي وفق سياسة الجهة، مراجعة دورية للصلاحيات، وتحديثات أمنية واختبار قبل التوسع. |

## بيانات الإعداد التي يقدمها مسؤول الجهة لاحقاً

سيحتاج مسؤول المؤسسة إلى تزويد فريق التشغيل بمعرف المستأجر، ومعرف التطبيق، ووسيلة اعتماد للخادم، وعنوان صندوق البريد المخصص، وتحديد موقع Teams والملف المستهدف. تحفظ القيم السرية في إعدادات بيئة آمنة فقط، ولا توضع داخل الكود أو ملفات Excel أو قنوات المحادثة.
