# استراتيجية قابلية النقل وتصدير بيانات المنصة

## الهدف

تستخدم المنصة حالياً MySQL/TiDB عبر Drizzle وS3 للمرفقات. هذا التصميم يتيح تصدير البيانات التشغيلية بصورة منظمة، لكنه لا يجعل PostgreSQL أو التشغيل المحلي مضموناً تلقائياً. لذلك تعتمد قابلية النقل على تصدير محايد ثم اختبار استيراد في بيئة منفصلة قبل أي انتقال.

## طبقات التصدير

| الطبقة | الصيغة المقترحة | المحتوى | الضابط |
|---|---|---|---|
| البيانات المرجعية | JSON وCSV | المستخدمون والملفات والوحدات والأدوار | إزالة الحقول السرية، والحفاظ على المعرفات والعلاقات. |
| البيانات التشغيلية | JSON Lines أو CSV | المهام والإجازات والحضور والنقاط والمراسلات وسجل التدقيق | تصدير متسلسل بالتاريخ مع بصمة SHA-256 لكل ملف. |
| المرفقات | manifest JSON مع مفتاح التخزين | اسم الملف، النوع، الحجم، البصمة، ومفتاح S3 | لا تُضمّن بيانات اعتماد أو روابط مؤقتة دائمة. |
| المخطط | SQL/Drizzle migration | تعريف الجداول والفهارس والقيم المعدودة | يراجع يدوياً قبل الاستيراد إلى PostgreSQL أو بيئة محلية. |

## ضوابط الخصوصية

يجب تشفير حزمة التصدير أثناء النقل والتخزين، وإخفاء الأسرار وملفات الجلسات ومفاتيح S3. لا يجوز أن يتضمن التصدير سجلات مستخدمين تجريبية أو بيانات غير مصرح بها. كل عملية تصدير واستيراد يجب أن تسجل المنفذ والوقت والنطاق والبصمة والنتيجة في سجل الحركة.

## اختبار النقل

يبدأ الاختبار بإنشاء قاعدة فارغة، ثم تطبيق المخطط، ثم استيراد البيانات المرجعية، ثم البيانات التشغيلية، ثم التحقق من عدد الصفوف والعلاقات والبصمات. بعد ذلك تُختبر قراءة لوحة القيادة وملف الموظف وسجل المهام والتقرير والحضور من البيئة المستوردة. لا تعتبر قابلية النقل مكتملة قبل نجاح هذا الاختبار في بيئة PostgreSQL أو On-Premise فعلية.

## ما يحتاج قراراً خارجياً

يتطلب التنفيذ الفعلي تحديد مالك وجهة التخزين، وسياسة الاحتفاظ، ونطاق البيانات المسموح تصديره، ومفتاح تشفير تديره الجهة. كما يتطلب تشغيل PostgreSQL أو On-Premise بيئة اختبار مستقلة؛ ولا ينبغي الادعاء بالتوافق الكامل قبل تنفيذ هذا الاختبار.
