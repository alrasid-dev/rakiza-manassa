# إعداد Firebase Authentication وFirestore لرَكيزة

تضيف رَكيزة Google والبريد/كلمة المرور كخياري دخول إضافيين. يبقى رمز OTP ومفتاح المرور (البصمة أو Face ID أو PIN) متاحين كما هما. تتحقق رَكيزة في الخادم من Firebase ID Token ثم تطابق البريد مع الحساب أو ملف الموظف في قاعدة بيانات رَكيزة قبل إنشاء جلسة الدخول.

## ما يُخزن في Firestore

لا تُخزن المهام أو الحضور أو الصلاحيات أو المراسلات في Firestore. بعد دخول ناجح فقط، تزامن رَكيزة مستنداً واحداً في `rakizaUsers/{uid}` يحوي البريد الرسمي والاسم ومرجع الحساب ومرجع الملف ومزود الدخول ووقت التحديث.

## قواعد Firestore المطلوبة

انسخ محتوى `firebase/firestore.rules` إلى **Firebase Console → Firestore Database → Rules** ثم اضغط **Publish**. القواعد تسمح للمستخدم بقراءة وثيقة هويته فقط، وتمنع الإنشاء والتعديل والحذف من المتصفح. كتابة المزامنة تقوم بها رَكيزة من الخادم باستخدام Service Account.

## التحقق من Authentication

في **Firebase Console → Authentication → Sign-in method**، فعّل Google وEmail/Password. يجب إبقاء خيار ربط الحسابات التي تستخدم البريد نفسه مفعلاً. وفي **Settings → Authorized domains** أضف نطاق رَكيزة المنشور. يقبل الخادم البريد المنتهي بـ`@moj.gov.sa`، مع الاستثناءات الإدارية المعتمدة سابقاً فقط.

## اختبار الاستلام

بعد نشر نسخة رَكيزة، أدخل إلى `/login` واختر تبويب **Google والبريد**. جرّب Google بحساب رسمي موجود في ملفات رَكيزة، ثم جرّب إنشاء كلمة مرور: تصل رسالة التحقق إلى البريد الرسمي، ولا يسمح بالخروج من Firebase إلى رَكيزة قبل توثيق البريد. لا تعتمد النجاح التشغيلي قبل اختبار حساب فعلي مرخص.
