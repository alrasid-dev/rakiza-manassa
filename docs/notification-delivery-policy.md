# سياسة تسليم الإشعارات والتصعيد

> **القاعدة المعتمدة:** الإشعار الداخلي داخل المنصة هو القناة التشغيلية المعتمدة حالياً. لا يعامل البريد الإلكتروني كبديل منفذ أو كدليل وصول إلى أن تعتمد الجهة Microsoft Graph وصندوق بريد خدمي وتفعّل المهام المجدولة في الإنتاج.

## نطاق التنفيذ الحالي

تنشأ الإشعارات الداخلية من الخادم فقط وتُربط بملف المستلم التشغيلي. يعرض مركز الإشعارات في شريط المنصة السجلات المخصصة للمستخدم، ويدعم تعليمها كمقروءة، كما يفتح إشعار إسناد المهمة مساحة المهمة المقصودة. لا يقبل العميل معرف ملف ليختار مستلم الإشعار، وتستمر ضوابط الدور والوحدة في تقييد السجلات المعروضة.

| الحدث التشغيلي | المستلم الداخلي المنفذ | حالة التنفيذ | مفتاح منع التكرار |
|---|---|---|---|
| إسناد مهمة يدوي | المكلف، والملازم المختار كنسخة عند وجوده | منفذ فور إنشاء المهمة | معرف المهمة والملف |
| تحديث Excel لمهام الملازمين | المكلف بالمهمة المستخرجة | منفذ عند معالجة التغيير | معرف المهمة المستخرجة |
| مهام اليوم المجدولة | المكلف بكل مهمة مستحقة | المنطق منفذ؛ التشغيل الحي ينتظر Heartbeat | اليوم والملف والمهمة |
| تأخر المهمة بعد ست ساعات | المكلف | المنطق منفذ؛ التشغيل الحي ينتظر Heartbeat | الملف والمهمة |
| إحالة المشرف والمساءلة بعد المهلة الإضافية | المكلف، مع سجل الإحالة الإداري | المنطق منفذ؛ التشغيل الحي ينتظر Heartbeat | الملف والمهمة |
| مراسلة أو طلب | النسخ المحددة في التسلسل | منفذ عند إنشاء المراسلة | المراسلة والملف ونوع المستلم |
| انتهاء الملازمة خلال سبعة أيام | ملف الملازم، مع عدد المتعثرات والمهام غير المكتملة | المنطق منفذ؛ التشغيل الحي ينتظر Heartbeat | الملف وتاريخ نهاية الملازمة |
| تذكرة دعم | مقدم التذكرة، ثم مدير الدعم، ثم الرئيس | المنطق منفذ؛ التصعيد الحي ينتظر Heartbeat | التذكرة ومرحلة التصعيد |

## مراحل التصعيد وقناة البريد

تلتزم المنصة بسياستين زمنيتين مختلفتين. تتبع المهمة التشغيلية مهلة ست ساعات أولى ثم ست ساعات إضافية قبل الإحالة الإشرافية والمساءلة. أما تذكرة الدعم فتمنح موظف الدعم 72 ساعة ثم مدير الدعم 24 ساعة قبل إحالة الرئيس. تبقى هذه المهل محسوبة في الخادم، ولا يرسل النظام إشعاراً جديداً عندما تكون العملية قد سُجلت بالمفتاح ذاته.

| المرحلة | القناة الآن | البريد المستهدف بعد الاعتماد | شرط التفعيل |
|---|---|---|---|
| الإسناد الأولي | إشعار داخل المنصة | اختياري وفق سياسة الوحدة | اعتماد سياسة الرسائل وصندوق الخدمة |
| تجاوز ست ساعات | إشعار داخل المنصة وسجل متعثر | المكلف والمشرف المحدد | تفعيل Heartbeat وMicrosoft Graph |
| الإحالة بعد 12 ساعة | إشعار داخل المنصة وسجل مساءلة | المشرف والرئيس بحسب التسلسل | تفعيل Heartbeat وMicrosoft Graph |
| تذكرة دعم بعد 72 ساعة | إشعار لمدير الدعم | مدير الدعم | تفعيل Heartbeat وMicrosoft Graph |
| تذكرة دعم بعد 96 ساعة | إشعار للرئيس | رئيس المحكمة | تفعيل Heartbeat وMicrosoft Graph |
| مراسلة أو طلب | إشعار للنسخ والمتلقين | المتلقون في التسلسل | اعتماد Graph وصندوق البريد |

بعد اعتماد البريد، تستخدم المنصة صندوق بريد خدمي تابعاً للجهة وأقل إذن مناسب من Microsoft Graph. تتطلب عملية `sendMail` إذن `Mail.Send`، ويعني رد `202 Accepted` قبول الطلب لا ضمان التسليم النهائي؛ لذلك يجب تسجيل محاولة الإرسال ومعرف الارتباط والنتيجة التشغيلية، دون وضع عنوان البريد أو رمز الوصول في سجل العميل. ## ضوابط الوصول والسرية

تتبع الإشعارات مبدأ **المنع الافتراضي**. يعرض الاستعلام الخادمي فقط الإشعارات المطابقة لملف جلسة المستخدم، ولا تصبح إشعارات القيادة أو الدعم أو الوحدة متاحة لمستخدم آخر لمجرد معرفة معرف المهمة أو التذكرة. تبقى المراسلات والمرفقات ضمن مسارات الصلاحية الأصلية؛ الإشعار لا يمنح صلاحية جديدة لقراءة محتوى خارج نطاق المستخدم.

تسجل الإجراءات الإدارية والتحويلات والتصعيدات في سجل الحركة. لا تظهر تفاصيل أخطاء Heartbeat أو مكدسات التنفيذ للعميل، وتبقى في سجل الخادم للاستخدام التشغيلي. قبل إدخال البريد المؤسسي، يراجع أمن المعلومات قائمة المستلمين، الصندوق الخدمي، سياسة الاحتفاظ، ومحتوى الرسالة لضمان ألا يصبح البريد قناة لتسريب بيانات قضائية.

## تشغيل ما بعد النشر

توجد معالجات Heartbeat ومفاتيح منع التكرار في المنصة، لكنها لا تعمل في بيئة التطوير أو قبل النشر. بعد نشر الموقع، ينشئ مالك المشروع الوظائف الفعلية، ويحفظ معرف كل وظيفة في إعدادات الجدولة، ويختبر كل وظيفة بحسابات تجريبية غير حساسة. لا تُفعل أي رسالة بريدية أو مزامنة Teams قبل اعتماد الجهة ومراجعة سجل التشغيل.
