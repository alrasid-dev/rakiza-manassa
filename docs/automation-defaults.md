# سياسة التشغيل الآلي الافتراضية

تعمل المنصة دون إعداد تشغيلي متكرر من مالكها بعد نشرها وتفعيل وظائفها المجدولة. تُستمد المهام من القوالب المستوردة، ويُسجل كل إنشاء أو تصعيد أو حركة نقاط في سجل التدقيق.

| العملية | الإعداد الافتراضي | النتيجة |
|---|---|---|
| إنشاء المهام | الساعة 07:00 صباحاً بتوقيت السعودية، من الأحد إلى الخميس | تنشئ المنصة المهام اليومية، وتتحقق من اليوم المحدد للمهام الأسبوعية والشهرية وربع السنوية. |
| إسناد القوالب المستوردة | تعيين تلقائي متوازن بين الموظفين الإداريين النشطين عند غياب مكلف صريح في ملف المصدر | لا تبقى المهمة بلا مكلف ما دامت ملفات موظفين إداريين نشطة موجودة. |
| الإشعار الداخلي | عقب إنشاء المهمة، مع منع تكرار السجل | يُنشأ إشعار في حساب المكلف يبين المهمة ووقت استحقاقها. |
| مهلة التنفيذ | ست ساعات من وقت جدولة المهمة | تُحدّث المهمة إلى متأخرة، ويُفتح متعثر تلقائي، ويُسجل خصم نقاط وإشعار تصعيد. |
| انتهاء الملازمة | فحص يومي قبل سبعة أيام أو أقل من تاريخ النهاية | يظهر تنبيه يتضمن المتعثرات المفتوحة والمهام غير المكتملة وحالة الاستعداد للانتقال. |
| الانتقال | بعد تثبيت دورة الملازمة وإقفال المتعثرات والمهام المطلوبة | تظهر حالة **جاهز للنقل**، وإلا تظهر الأسباب بجانب اسم الملازم. |

> لا يُرسل البريد الإلكتروني في النسخة الحالية لأن ربط Microsoft 365 مؤجل بطلب الجهة. تُنشأ الإشعارات داخل المنصة وسجل التدقيق فوراً، ويُفعّل الإرسال البريدي من المصدر نفسه عند إقرار الربط المؤسسي.

## تفعيل الوظائف المجدولة بعد النشر

تحتاج الوظائف المجدولة إلى نشر المنصة أولاً؛ لأن بيئة التطوير لا تستقبل التشغيل الدوري. بعد النشر، تُنشأ ثلاث وظائف مملوكة للمنصة وتحفظ معرفاتها في سجل الإعدادات:

| الوظيفة | التعبير الزمني بتوقيت UTC | المسار |
|---|---|---|
| إنشاء المهام والتنبيه اليومي | `0 0 4 * * 0-4` | `/api/scheduled/daily-task-reminder` |
| فحص التصعيد | `0 0 * * * 0-4` | `/api/scheduled/task-escalation` |
| فحص قرب انتهاء الملازمة | `0 0 3 * * *` | `/api/scheduled/trainee-due-soon` |

يتحقق كل مسار من هوية الوظيفة المجدولة ومن معرفها المحفوظ في قاعدة البيانات، ويتعامل مع إعادة المحاولة دون تكرار المهام أو الإشعارات.
