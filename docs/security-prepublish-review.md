# مراجعة الحماية قبل النشر

> **حدود المراجعة:** هذه مراجعة تصميم وكود واختبارات آلية؛ لا تعني أن التطبيق «غير قابل للاختراق». لا يجوز نشر بيانات قضائية حساسة قبل مراجعة جهة تقنية مختصة واختبار اختراق مستقل.

## الضوابط المنفذة حالياً

| المجال | الوضع | الدليل في المنصة |
|---|---|---|
| مصادقة المسارات | منفذ | كل إجراءات المحكمة التشغيلية تستخدم `protectedProcedure`؛ المسار العام المقصود هو طلب التسجيل فقط، إضافةً إلى فحص الصحة التقني. |
| تحقق الصلاحية داخل الخادم | منفذ | التحقق لا يعتمد على إخفاء الواجهة؛ المسارات تعيد `FORBIDDEN` عند غياب الدور أو النطاق الصحيح. |
| التسلسل القيادي | منفذ | رئيس المحكمة والرئيس المساعد ضمن نطاق قيادي شامل. أما مدير شؤون الملازمين فيخضع للوحدة التنظيمية المفوضة له. |
| عزل البيانات الذاتية | منفذ | الموظف أو الملازم أو القاضي غير القيادي يرى ملفه ومهامه فقط؛ وتتحقق الخدمة من ملف المستخدم على الخادم. |
| عزل القسم | منفذ في المسارات الأساسية | قوائم الأفراد والمهام تتقيد بالوحدة المفوضة لمدير القسم، مع منع إسناد مهمة خارجها. الموظف الإداري يرى ملفه وملازمي وحدته فقط، ولا يحصل على التقارير أو مهام الموظفين الآخرين. |
| سجل الحركة | منفذ | تسجل العمليات الإدارية والتفويضات في سجل تدقيق مع المنفذ والوقت والكيان. |
| حفظ المرفقات | منفذ | تحفظ المرفقات في تخزين منفصل عبر الخدمة المهيأة، مع حفظ المرجع في قاعدة البيانات بدلاً من حفظ البايتات داخلها. مرفقات الدعم مقصورة على PNG وJPEG وWebP، بحد 2 ميغابايت للمرفق وباسم وامتداد وبصمة ثنائية متوافقة قبل التخزين. |
| فحص مصدر Excel | منفذ | بصمة المحتوى تمنع تكرار المعالجة، والمرشح يقصر الصفوف التشغيلية على الملازمين القضائيين. |
| التحقق من الإدخالات | منفذ | عقود tRPC تستخدم Zod للتحقق من الحدود والأنواع قبل تنفيذ العمليات. |
| بديل الإجازة | منفذ | الموظف الإداري يتلقى قائمة بدلاء إداريين نشطين من وحدته فقط؛ لا تعتمد الواجهة على قائمة الأفراد العامة. |
| واجهات الدور | منفذ | تخفي واجهات المهام والحالة والمراسلات النماذج وخيارات التوجيه غير المصرح بها، مع بقاء المنع الخادمي هو الضابط الحاسم. |
| أخطاء معالجات الجدولة | منفذ | تقيد المعالجات التنفيذ بمهام Heartbeat الموثقة، وتستخدم استجابة فشل موحدة تسجل الخطأ خادمياً من دون إعادة رسالة الخطأ أو المكدس أو سياق المسار إلى العميل، بما في ذلك معالج تنبيه انتهاء الملازمة. |
| أخطاء tRPC العامة | منفذ | يحذف مهيئ tRPC حقل المكدس من كل استجابة خطأ؛ تحافظ أخطاء التفويض والتحقق المقصودة على رسالتها العربية، بينما تستخدم الأخطاء غير المتوقعة رسالة عامة ويُسجل سياقها في الخادم فقط. |
| مؤشر الأداء | منفذ بإرشاد محدود | يستخرج المؤشر من حركات النقاط المعتمدة المرتبطة بالإنجاز والتأخر والمساءلات، ويعرض لصاحب الملف فقط كمؤشر متابعة لا كقرار وظيفي مستقل. |
| كوكي الجلسة والخروج | منفذ مع حد معروف | كوكي الجلسة `HttpOnly` ومقيد بالمسار، ويفرض `Secure` عند HTTPS؛ يتحقق رجوع OAuth من `nonce` قصير العمر، ومسار الخروج يمسح الكوكي بالخصائص نفسها. |
| منشأ طفرات tRPC | منفذ | ترفض طبقة tRPC طلبات `POST` التي لا تحمل منشأً مطابقاً للنطاق والبروتوكول الفعليين، للحد من الطلبات العابرة للمواقع. |
| رؤوس المتصفح وسياسة المحتوى | منفذ | يضيف الخادم `nosniff` و`Referrer-Policy` و`Permissions-Policy` في جميع البيئات، ويضيف في الإنتاج CSP تقيد المصادر والكائنات والنماذج وإطارات الطرف الثالث مع استثناءات Teams والخطوط اللازمة فقط. |

## متطلبات حجب النشر للبيانات الحساسة

| المطلوب | السبب | الإجراء المطلوب من الجهة |
|---|---|---|
| اعتماد Microsoft Entra ID مع MFA | المصادقة المؤقتة لا تكفي لبيئة قضائية إنتاجية | تسجيل تطبيق مؤسسي، ربط الحسابات الرسمية، وتطبيق سياسة وصول مشروط ومصادقة متعددة العوامل. |
| فحص برمجيات خبيثة للمرفقات | تحليل Excel لا يغني عن فحص DOCX أو PDF أو الملفات الضارة | اعتماد خدمة فحص ملفات داخل بيئة الجهة أو مزود معتمد قبل إتاحة الملفات للمستخدمين. |
| قائمة امتدادات وحجم ملفات صريحة | تقليل خطر الملفات الضارة واستهلاك السعة | قصر الرفع الحالي على امتدادات العمل المطلوبة وفرض حد حجم بعد موافقة الجهة. |
| حماية من الإساءة ومعدل الطلبات | تقليل محاولات التخمين أو الإغراق | تفعيل حد للطلبات وتسجيل تنبيهات الفشل على بوابة النشر أو موازن الحمل. |
| اختبار اختراق مستقل | التحقق الواقعي من العزل والمنطق التجاري | تكليف فريق أمن معلومات أو مزود معتمد باختبارات تفويض أفقي وعمودي، ورفع النتيجة قبل إطلاق البيانات الحساسة. |
| مراجعة دورية للصلاحيات | منع تراكم الصلاحيات المؤقتة | مراجعة شهرية لتفويض الرئيس المساعد ومديري الأقسام وسحب ما انتهت الحاجة إليه. |
| إبطال مركزي للجلسات | مسح كوكي المتصفح لا يبطل كل الرموز الصادرة عند الاشتباه بتسرب جلسة | اعتماد Entra ID وسياسة إبطال الجلسات أو إضافة قائمة جلسات خادمية قبل تشغيل بيانات قضائية حساسة. |

## منهج العزل المعتمد

تطبق المنصة مبدأ **المنع الافتراضي**: المستخدم لا يحصل على بيانات لمجرد تسجيل دخوله، بل يلزم أن يطابق دوره ونطاق القسم أو علاقته بالسجل. هذا يتوافق مع توصية OWASP بفرض أقل صلاحية والتحقق من التفويض عند كل طلب، لا في الواجهة فقط. [1]

تشمل اختبارات المراجعة الحالية اختباراً لمسار الموظف الإداري يثبت أن المسار يعرض ملفه وملازمي وحدته، ويقصر المهام على ملفه، ويرفض استعلام التقرير. كما يوجد اختبار منفصل لقائمة بديل الإجازة المقيدة بالوحدة، واختبارات لسياسة عرض طلبات الملازم والموظف والقيادة، واختبار لمعالجات الجدولة يثبت حجب تفاصيل الخطأ في وظيفة أتمتة المهام وفي تنبيه انتهاء الملازمة، إضافة إلى اختبار مهيئ tRPC. كما تتحقق اختبارات جديدة من خصائص كوكي الجلسة وتسجيل الخروج ورفض طفرات tRPC بلا منشأ أو بمنشأ مختلف. لا تغني هذه الاختبارات عن اختبار اختراق مستقل أو مراجعة حسابات الجهة الفعلية.

## المرفقات

توصي OWASP بقائمة امتدادات مسموح بها، وعدم الثقة في نوع المحتوى المعلن من المتصفح، وتقييد الحجم، وعزل التخزين، وفحص مكافحة البرمجيات الخبيثة عند الإمكان. التخزين الحالي منفصل، لكن الفحص المضاد للبرمجيات الخبيثة وقوائم الامتدادات النهائية يحتاجان قراراً مؤسسياً قبل النشر. [2]

## قرار النشر

**مسموح بالمراجعة التجريبية للبيانات غير الحساسة فقط.** أما النشر التشغيلي لملفات وأعمال المحكمة فيتطلب إغلاق البنود الحاجبة أعلاه، وتحديد مالك أمني لدى الجهة، ومراجعة النطاقات والأدوار الفعلية للحسابات قبل الإتاحة.

## تحديث ركيزة: البصمة والتطبيق

اسم التطبيق الرسمي الحالي هو **رَكيزة**، وبيان PWA يستخدم الاسم نفسه. المصادقة الحالية لا تستخدم البصمة أو Face ID؛ بل تعتمد على OAuth/جلسة JWT وخصائص كوكي الجلسة الموضحة أعلاه. لا تُخزّن المنصة بصمات المستخدمين، ولا ينبغي تنفيذ ذلك؛ المسار الصحيح هو Passkeys/WebAuthn بحيث يبقى المفتاح الخاص داخل الجهاز أو مدير مفاتيح النظام وتتحقق الخدمة من المعرّف العام فقط.

المنصة حالياً **PWA قابلة للتثبيت** وليست تطبيق Android/iOS أصلياً. عامل الخدمة يمرر طلبات التشغيل إلى الشبكة ولا يخزن بيانات تشغيلية أو ردود API حساسة محلياً. يلزم اختبار تثبيت فعلي على أجهزة الجهة بعد النشر، كما يلزم تطبيق أصلي فقط إذا تطلبت الجهة تكاملات حيوية أو سياسات متجر/إدارة أجهزة لا يغطيها PWA.

هذا التحديث لا يرفع قرار النشر الحساس: ما زال تفعيل Microsoft Entra/MFA أو Passkeys واختبار الاختراق المستقل والإبطال المركزي للجلسات وفحص الملفات الخبيثة متطلبات قبل إدخال بيانات قضائية إنتاجية.
